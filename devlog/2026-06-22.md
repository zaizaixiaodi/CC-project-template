## 关键决策
- **加工作日志、但放独立文件夹**：之前否决过 devlog，理由是怕污染常驻上下文。本次重启该需求，靠"单独文件夹 + 平时不自动读 + 按天按需读"绕开原顾虑——所以这不是当初否决的那个东西。
- **三层各司其职**：PLAN=做到什么算完 / HANDOFF=现在在哪 / 工作日志=曾经发生什么，互不重复。日志只记 git 记不下的"为什么"，不逐文件列改动，避免沦为无人看的流水账。
- **文件名用 `YYYY-MM-DD`** 而非 `YYMMDD`：排序天然正确、一眼是日期。
- **插件化推迟**：脚手架还没实测，等稳定再 skill 化/插件化，设计先存进参考文章。
- **（第二轮）不装官方 skill-creator，只借其结构与规则**：它对文档工作流过重（带评测/打包/description 优化全套）；且我们没有 active 的内置造-skill 能力，造 skill 靠通用文件工具 + structure-guide。所以只把它的目录约定和校验规则吸收进 guide。
- **结构自检避开"允许键清单"**：官方校验器只认 6 个键，会把 Claude Code 合法的 `disable-model-invocation`/`argument-hint` 判违法。自检只收通用安全规则（kebab-case 命名、name/description 必填、description 不含尖括号、长度上限），并明确警示别拿官方脚本直接验本仓库 skill。
- **（第三轮）日志改名 worklog→devlog**：用英文 `devlog/` 而非中文，与脚手架将来跑业务工作流时产出的"工作日志"（业务产物）彻底区分，避免混淆。三层关系也钉清：handoff 是跨会话地基、plan 是建在其上的复杂任务协议层（plan 依赖 handoff）、devlog 最普适（每轮都写）。
