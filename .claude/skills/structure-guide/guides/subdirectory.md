# 拆/建子目录 CLAUDE.md 指南

## 何时用本指南

- 根 CLAUDE.md 接近或超过 200 行
- 根 CLAUDE.md 出现"如果你在 X 目录下……"这类条件语句
- 项目有 ≥ 3 个明显不同的业务域/模块

## 何时不用

- 单人项目、规则全局通用 → 不需要拆
- 项目目录无明显领域划分 → 不需要拆
- 想按"文件类型"触发规则（如只在 .md 文件触发） → 跳 `rule.md`，用 `rules/` + `paths:` 更合适

---

## 核心方法论

### 加载机制

Claude Code 启动时，从**当前工作目录**沿目录树向上遍历，收集路径上所有 `CLAUDE.md`，**从具体到泛化**合并加载（叶子目录优先级最高，根目录最低）。

例：在 `contracts/` 目录启动 Claude，加载顺序为：
```
contracts/CLAUDE.md  (最具体，优先级最高)
        ↓
根 CLAUDE.md         (全局规则，优先级最低)
```

**不会加载** `litigation/CLAUDE.md`——上下文干净，规则精准。

### 子目录启动 vs 根目录启动

| 维度 | 根目录启动 | 子目录启动 |
|------|---------|---------|
| 上下文加载 | 所有文件 | 仅当前路径向上 |
| 搜索范围 | 全仓库 | 收敛到子目录 |
| 适用场景 | 跨多个模块的变更 | 单一模块内任务 |

**操作建议**：改某模块就 `cd` 到该模块后启动 Claude。

---

## 决策规则

| 情况 | 方案 |
|-----|------|
| 业务域 ≤ 2 个 | 不拆，单 CLAUDE.md 用 `##` 分节即可 |
| 业务域 ≥ 3 个 | 每个域建子目录 + `CLAUDE.md` |
| 根文件出现"如果在 X 任务……" | 拆分信号，对应内容迁子目录 |
| 子目录文件 < 10 行 | 太细，合并回根文件 |
| 高风险/敏感模块（如 auth/支付） | 即使内容少也要独立子目录 CLAUDE.md，放安全红线 |

### 行数目标

- 根目录：50-60 行（指针 + 全局约定）
- 子目录：20-30 行（该域特有规则）

---

## 模板

子目录 `<domain>/CLAUDE.md`：

```markdown
# <目录名> — <业务域说明>

## 范围
本目录管理：<本域职责>
不管理：<明确排除，指向其他目录>

## 约定
- <该域特有规则 1，具体可验证>
- <该域特有规则 2>

## 命令
- <该域专用命令，如有>

## 注意事项
- <已知陷阱或特殊限制>
```

## 常见错误

| 错误 | 后果 | 正确做法 |
|------|------|--------|
| 子目录 CLAUDE.md 写 < 10 行 | 拆分太细，反而增加维护成本 | 合并回根文件 |
| 子目录文件重复根文件的内容 | 上下文浪费 | 只写该域**特有**的规则 |
| 拆分后忘了在根文件加导航指针 | Claude 不知道有子文件 | 根文件"目录导航"节列出子文件 |
| 拆错维度（按文件类型而非业务模块） | 该用 `rules/ + paths:` | 跳 `rule.md` |
| 同一规则同时出现在根和子文件 | 冲突时无法判断优先级 | 子文件优先级高，避免重复 |

- [ ] 根 CLAUDE.md ≤ 60 行
- [ ] 根文件"上下文路由"节列出了所有子文件
- [ ] 没有规则同时出现在根和子文件
- [ ] 子文件只写该域**特有**的规则
