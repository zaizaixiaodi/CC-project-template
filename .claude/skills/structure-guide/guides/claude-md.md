# 写/改 CLAUDE.md 指南

## 何时用本指南

- 用户要新建项目根 `CLAUDE.md`
- 用户要修改现有根 `CLAUDE.md`
- 用户说"CLAUDE.md 太长了" / "怎么写一个好的 CLAUDE.md"

## 何时不用

- 用户要新建**子目录** CLAUDE.md → 跳 `subdirectory.md`
- 用户要写"按文件类型触发的规则" → 跳 `rule.md`
- 用户要写多步骤工作流 → 跳 `skill.md`

---

## 核心方法论

### CLAUDE.md 是项目的宪法，不是百科全书

它在**每次会话开始时自动加载**进上下文。Claude 在整个会话里都能看到。

**写什么** vs **不写什么**：

| 应该写 | 不应该写 |
|--------|---------|
| 项目是什么（一句话定位） | 项目历史、创始故事 |
| 禁止使用的工具/方法（具体） | 公司价值观、愿景陈述 |
| 具体可验证的编码/写作规范 | "写高质量内容"这类模糊指令 |
| 常用命令（启动、测试、格式化） | 已有文档记录的内容（改为指针） |
| 高风险操作的红线 | 偶尔才用到的专项流程（放 skills） |

### 指针式 vs 字典式

CLAUDE.md 的职责是告诉 Claude **去哪找信息**，而不是存储全部信息：

```markdown
## Project Context
- 架构总览：`docs/architecture.md`
- API 文档：`docs/api.md`
- 部署流程：`docs/deploy.md`
- 合同业务专属规范：`contracts/CLAUDE.md`
```

### 黄金标准

新人第一次打开 CLAUDE.md，30 秒内能回答：项目定位 + 在哪工作 + 不能碰什么。

---

## 决策规则

| 情况 | 方案 |
|-----|------|
| 文件超过 **200 行** | 立即拆分（迁移到 `rules/` 或子目录 CLAUDE.md，跳 `subdirectory.md`） |
| 出现"如果在处理 X 任务……"条件句 | 分层信号，对应内容迁出根文件 |
| 出现模糊指令（"写干净的代码"） | 改写为具体可验证规则（"禁止 any，单文件不超过 200 行"） |
| 出现项目历史、营销叙事 | 删掉 |
| 反复出现的多步骤流程 | 抽出成 skill，CLAUDE.md 留指针 |
| 个人偏好（不想团队共享） | 迁到 `CLAUDE.local.md`（不提交 git） |

## 模板

新建/重写 `CLAUDE.md`：

```markdown
# <项目名称>

## 项目定位
<一句话：是什么 + 面向谁 + 核心目标>

## 技术栈/工具栈
- <工具 1>
- <工具 2>

## 禁止事项（非明确要求不得引入）
- <具体禁止项 1，5 秒内可判断是否违规>
- <具体禁止项 2>
- <具体禁止项 3>

## 编码/写作规范
- <规则 1：具体可验证>
- <规则 2>

## 工作风格
- <回复语言/格式偏好>
- <方案先行还是直接执行>

## 上下文路由
- 架构总览：`docs/architecture.md`
- <子目录名>/：<负责的领域>
- 多步骤流程见 `.claude/skills/`
```

## 常见错误

| 错误 | 后果 | 正确做法 |
|------|------|--------|
| 超过 200 行 | 后半段被 Claude 忽略 | 拆到 `rules/` 或子目录 CLAUDE.md |
| 写"写干净的代码"等模糊话 | Claude 无所适从 | 改写为可验证规则 |
| 把多步骤 SOP 写在 CLAUDE.md | 文件膨胀 | 抽出成 skill，留指针 |
| 塞进项目历史/创始故事 | 浪费 token | 删掉，保留事实 |
| 个人偏好写进 CLAUDE.md 并提交 | 污染团队 | 迁 `CLAUDE.local.md` |
| 缺少"禁止清单" | Claude 引入冲突依赖 | 写 "Do NOT introduce" 区块 |

## 完成后自检

- [ ] 总行数 ≤ 200
- [ ] 含"项目定位"一句话
- [ ] 含"禁止事项"列表（至少 3 条）
- [ ] 所有规则 5 秒内可判断是否违规
- [ ] 详细内容用指针引向其他文件，不堆在主文件
- [ ] 没有项目历史、营销叙事
